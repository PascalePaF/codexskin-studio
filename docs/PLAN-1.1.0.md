# CodexSkin Studio 1.1.0 实施计划

计划日期：2026-09-26（Asia/Tokyo）

## 目标

1. 把孤立的浅色和深色主题组织成可一次应用的昼夜组合。
2. 让 ChatGPT 使用 `system` 外观模式，根据操作系统明暗偏好自动选择对应槽位。
3. 用完全本地的收藏和最近使用记录减少重复寻找。
4. 扫描本机字体，让用户选择真实存在的 UI 与代码字体，同时继续允许手动输入。
5. 保持 1.0.0 的双重主题校验、完整备份、键级恢复、原子替换和官方字符串兜底。

## 用户故事

- 作为经常切换日间和夜间工作的用户，我希望一次应用两套协调配色，此后随系统自动切换。
- 作为有固定偏好的用户，我希望收藏主题或组合，并快速回到最近用过的选项。
- 作为重视中文和代码显示的用户，我希望直接看到本机字体，而不是猜字体名称。
- 作为已有 1.0.0 数据的用户，我希望升级后无需迁移配置，原来的主题与恢复点继续可用。

## 技术方案

### 主题组合

- 新增 `ThemePair` 数据模型，引用一套 `light` 与一套 `dark` 主题。
- Rust 新增 `apply_theme_pair` 命令，在一次事务中验证并写入两个槽位。
- 组合应用只创建一次完整备份和一次撤销快照，最后把 `appearanceTheme` 设为 `system`。
- 单主题应用继续只写对应槽位，不改变既有操作方式。

### 收藏与最近使用

- 使用版本化键 `codexskin.preferences.v1` 存在本机 WebView localStorage。
- 只记录公开主题/组合 ID，不保存聊天、账号、路径或任何敏感内容。
- 数据损坏、存储被禁用或旧字段缺失时自动回到空偏好，不影响主题应用。
- 最近记录去重并限制为 6 项。

### 系统字体

- Windows 从 HKLM/HKCU 字体注册表读取显示名称，合并样式变体并去重。
- macOS/Linux 优先使用 `fc-list`；不可用时返回跨平台安全候选。
- 后端最多返回 320 个字体系列，前端通过原生 datalist 搜索选择。
- 字体名称继续经过长度、控制字符、CSS/URL 片段校验。

## 明确不做

- 不同步收藏到云端，不要求账号。
- 不下载或安装字体。
- 不按计划任务强制切换主题；系统跟随由 ChatGPT 原生模式负责。
- 不改变图片壁纸、CSS 注入与布局增强仍属于后续 Experimental 的决定。

## 验收标准

- 4 个主题组合全部引用有效且明暗类型正确的预设。
- 组合应用后浅色、深色 Chrome 主题和代码主题槽位同时存在，模式为 `system`。
- 收藏、最近使用、上次选择可在重启工具后恢复，异常存储不会导致白屏。
- Windows 能列出本机字体；浏览器演示模式提供稳定的示例字体。
- 1.0.0 的单主题应用、导入导出、撤销与恢复测试继续通过。
- TypeScript 构建、Vitest、Rust tests、rustfmt、Clippy、Tauri Release 构建全部通过。

## 发布步骤

1. 完成功能和自动化测试。
2. 在默认与 1024×768 窗口完成交互验收。
3. 生成 1.1.0 Windows x64 可执行文件和 NSIS 安装器。
4. 记录大小、版本和 SHA-256。
5. 初始化 Git `main` 分支并确认忽略构建缓存。
6. 使用授权 GitHub 账号创建公开仓库并推送初始提交。
